# Design: extract `internal/proxy` package (behaviour-preserving)

Date: 2026-05-16
Status: approved (brainstorming)
Branch: `refactor/extract-internal-proxy` (off `master`)

## Context

`spnego-proxy` is a single `package main` (45 `.go` files, all logic + CLI +
tests in one package). ClusterFuzzLite/OSS-Fuzz cannot fuzz it: its
`compile_native_go_fuzzer` autogenerates a harness that imports the target
package by module path, and Go cannot import `package main`. The blocked
ClusterFuzzLite migration (PR #224) fails with:

```
<autogenerated>:1: mismatched import path, have "main", want "github.com/andrewesweet/spnego-proxy"
```

Native `go test -fuzz` tolerates `package main`; ClusterFuzzLite does not.
This project extracts the fuzzed proxy logic into an importable package so the
ClusterFuzzLite work can resume. It is a **prerequisite refactor**, not a
behaviour change. PR #224 rebases on this once merged.

## Goal & non-goals

**Goal:** make the proxy logic and its fuzz targets live in an importable
package, with zero observable behaviour change.

**Non-goals (YAGNI):** no logic refactor, no behaviour change, no new tests,
no dependency changes, no entrypoint redesign, no public Go API. Pure
move + package rename + minimal capitalisation.

## Decisions (locked in brainstorming)

1. **Package:** `internal/proxy` — module-private. Importable by `main` and by
   `go-118-fuzz-build` within the module (ClusterFuzzLite works), not by
   external modules. Consistent with the repo SemVer policy: the public API is
   the CLI contract, **explicitly not the Go API** (CLAUDE.md § Versioning), so
   the Go package stays private and reshapeable.
2. **Shim boundary:** `package main` keeps `main.go` (entrypoint + `init()`
   slog handler), `version.go` (ldflags `-X main.version` / `-X main.commit`
   **unchanged**), `cli.go` (`cliConfig`, `parseFlags`, `buildProvider`).
   `internal/proxy` holds the logic, auth, tests, and fuzz targets, exposing
   `Serve` plus the config/types/constructors `main` needs. ldflags and the
   release pipeline are untouched (smallest blast radius).

## Target layout

```

    gss_darwin.c gss_darwin.h
```

## main ↔ proxy exported surface (the ONLY new exports)

Capitalise at definition + all call sites (mechanical rename, `gofmt`):

- Types: `Config` (was `ProxyConfig`), `ForwardingConfig`, `UpstreamTLSConfig`,
  `TokenProvider`, `NoProxyMatcher`.
- Constructors / funcs `main` calls: `NewNoProxyMatcher`,
  `NewGokrb5TokenProvider`, `NewNativeTokenProvider`, the circuit-breaker
  constructor, `Serve`, `GenerateViaPseudonym`, `SplitCSV`, `ParseAllowList`,
  `ResolveNoProxy`, and `UpstreamTLSConfig`'s build method
  (`BuildTLSConfig`).
- Package var: `LogLevel` (was `logLevel`, `*slog.LevelVar`) — `main.go`'s
  `init()` wires it into the slog handler and `main()` flips it on `-debug`.

Everything the **unit/fuzz tests** touch (`sameHost`, `ipAllowed`,
`extractHost`, `splitCSV`-internal, `validateResponseContentLength`,
`isValidFieldName`, `hasForbiddenFieldValueByte`, `validateResponseHeaderBytes`,
`connectPortAllowed`, `connectPortWildcard`, `stripIPv6Brackets`, `Match`, …)
**stays unexported** — the moved `_test.go` files are *in-package*
(`package proxy`, not `proxy_test`), preserving unexported access with no
export churn. `buildProvider` stays in `cli.go` (it consumes `cliConfig`) and
calls the exported `proxy` constructors, so no `main` type leaks into `proxy`.

## Behaviour-preservation invariants (must not change)

CLI flag names/types/defaults/usage text; exit codes (the 0/1/2 paths in
`main()`); `-version` output string; JSON-on-stderr log format; HTTP error
response bodies; Via / Forwarded / X-Forwarded-* header behaviour; CONNECT
tunnelling semantics. No logic hunks — `git diff` shows only file moves,
`package` clause changes, and identifier capitalisation.

SemVer: `refactor:` → **no version bump** (CLAUDE.md § Versioning).

## Compile-safe migration order

Each step leaves the tree building:

1. `git mv` the 15 logic + 4 auth + 2 C files + all logic/unit/fuzz `_test.go`
   into `internal/proxy/`; bulk `package main` → `package proxy` on moved
   files only.
2. Capitalise the §"exported surface" identifiers at definition and every
   call site (including inside `main.go`/`cli.go`).
3. Reduce `main.go`/`cli.go` to import
   `github.com/andrewesweet/spnego-proxy/internal/proxy` and call the exported
   surface; `version.go` unchanged.
4. `git mv testdata/fuzz` → `internal/proxy/testdata/fuzz`.
5. `go build ./... && go test -count=1 ./...` green (Linux, `CGO_ENABLED=0`).
6. Documentation path fixes forced by the move (see next section).

## Documentation changes forced by the move

`CONTRIBUTING.md` § Fuzzing and `CLAUDE.md` § Fuzzing reference the old
single-package paths; the move requires updating:

- Local fuzz command `go test -run '^$' -fuzz '^FuzzNoProxyMatch$'
  -fuzztime=60s .` → run against `./internal/proxy` instead of `.`.
- Crash-reproducer path `testdata/fuzz/<Target>/` →
  `internal/proxy/testdata/fuzz/<Target>/`.

These are the only doc edits; the fuzz *rules* and the `fuzz.yml` matrix note
are unchanged on this branch (the ClusterFuzzLite branch owns CFL-specific doc
changes).

## Verification (end-to-end)

- `go build ./...` (Linux) and `CGO_ENABLED=1 go build ./...` (darwin path:
  cgo GSS still links from `internal/proxy`).
- `go test -count=1 ./...` — every pre-existing test passes unchanged
  (including the committed `FuzzNoProxyMatch` reproducer replay).
- `golangci-lint run` clean.
- `git diff master --stat` shows renames/moves; a content review confirms no
  logic hunks (only `package`/identifier-case lines).
- CLI smoke: `./spnego-proxy -version` and `-help` produce byte-identical
  output and the same exit codes as `master`.
- Follow-on: PR #224 rebased — `.clusterfuzzlite/build.sh` module path flips to
  `github.com/andrewesweet/spnego-proxy/internal/proxy`; `compile_native_go_fuzzer`
  resolves; the original blocker is gone.

## Risks

- **Hidden logic edit during the mechanical rename.** Mitigated by the
  "no logic hunks" diff review gate and the unchanged test suite.
- **darwin/cgo path only buildable on macOS.** Linux CI proves the non-cgo
  build + tests; the cgo GSS file move is package-rename only (no C changes),
  and `auth_gss_darwin_test.go` continues to gate behind `//go:build darwin`.
- **Identifier collision when capitalising** (e.g. an exported name already
  exists). Checked during step 2; resolve by keeping the existing exported
  name.
